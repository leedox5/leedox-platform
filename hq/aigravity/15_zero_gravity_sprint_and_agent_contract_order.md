# 15화: 무중력 스프린트와 에이전트 계약 발주 프로토콜

> **Phase 4: Handoff 2.0 계약 발주, 무중력 스프린트 & 자율 PR 배포**  
> **Key Objective**: 기존의 비대하고 지루한 아자일 스프린트를 대신하여, 1시간 이내에 기획부터 배포 피드백까지 몰입 완수하는 '무중력 스프린트(Zero-Gravity Sprint)'와 독립된 AI 에이전트 간의 100% 안전한 '에이전트 계약 발주(Handoff 2.0 Order Protocol)'를 구축한다.

---

## 📖 1. 2주 스크럼을 대체하는 '1시간 무중력 개발'의 탄생

전통적인 IT 소프트웨어 개발에서 쓰이는 '스프린트(Sprint)'는 보통 2주에서 4주 단위의 긴 호흡으로 진행됩니다. 팀 전체가 모여 지루한 스크럼 회의, 스토리 포인트 산정, 데일리 스탠드업을 거치며 문서 작업에 많은 에너지를 소모합니다.

하지만 AI 에이전트와 인간 베테랑 개발자가 1:1로 페어 프로그래밍을 진행하는 **Antigravity 환경**에서는 이러한 방식이 오히려 컨텍스트 윈도우를 오염시키고 환각(Hallucination)을 유발하는 독이 됩니다.

디렉터 토미(Tommy)와 HQ 에이전트는 Handoff 0001부터 0017에 이르는 실전 마일스톤을 거치며, **'1시간 무중력 스프린트'**와 **'에이전트 계약 발주'**라는 혁신적인 에이전틱 아자일(Agentic Agile) 워크플로우를 완성했습니다.

```text
       [ 💡 백로그 (Idea Vault) ] 
                 │
                 ▼  (토미 감독님의 선택 & HQ 스펙 구체화)
       [ 🚀 무중력 스프린트 (1시간 몰입 단위) ]
                 │
                 ▼  (0000.md 스펙 계약 작성)
       [ 📮 에이전트 계약 발주 (Handoff Issue) ]
                 │
                 ▼  (WSL Symlink 0-Copy 실시간 연동)
       [ 🛠️ DEV 구현 & 100% 그린 검증 & 동료 편지 ]
```

## 🚀 2. 무중력 스프린트 (Zero-Gravity Sprint) 핵심 원칙

### 1) 1시간 콤팩트 스코프 (Compact 1-Hour Scope)
- 아무리 거대한 아키텍처 개편(예: 동적 메인 홈 카탈로그 `BL-0012`)이라도, 1시간 이내에 확실히 구현하고 검증할 수 있는 **Phase 1, Phase 2, Phase 3 단위로 분할**하여 발주합니다.
- 긴 호흡으로 코드를 이끌어가지 않아 에이전트의 기억(Context)이 오염되지 않으며, 집중 몰입도를 극대화합니다.

### 2) 실시간 런타임 피드백 루프 (Instant Feedback Loop)
- 코드 수정 후 즉시 로컬 서버(`http://localhost:3000/`) 또는 Railway 라이브 프로덕션에서 시각적/기능적 검증을 끝냅니다.
- 기획(HQ)과 구현(DEV)의 결과물이 수분 내에 눈앞에 나타나므로 수정 피드백이 즉각적으로 반영됩니다.

### 3) 100% Revertable 피처 브랜치 전략 (Feature Branch Isolation)
- 주요 구조 변경 시 단일 피처 브랜치(Draft PR) 상에 Handoff 0013, 0014, 0015를 차곡차곡 누적 푸시합니다.
- 토미 감독님의 최종 승인 시 **1-Click 머지**, 원치 않을 경우 **100% 깔끔한 Revert 가용성**을 원천 보장합니다.

## 📮 3. 에이전트 계약 발주 (Agent Contract Order Protocol)

### 📄 1) 파일 기반 입출력 계약 (`0000.md` ↔ `result.md`)
- HQ 에이전트와 DEV 에이전트는 서로 직접 메모리를 공유하지 않습니다.
- HQ 에이전트가 `handoff/<number_slug>/0000.md` 계약서를 작성하여 발주하면, DEV 에이전트가 코드를 작성하고 `handoff/<number_slug>/result.md` 결과서로 응답합니다.

### 🛡️ 2) `PR Required` 품질 가드
- **`PR Required: No`**: 1시간 미만 소규모 UI 정제, 단순 오타 수정 (main 브랜치 직접 푸시).
- **`PR Required: Yes`**: 어드민 요금 관리, DB 스키마/커머스 로직 개편 (피처 브랜치 + GitHub PR 머지).

### 💌 3) 마스터 배달원 토미와 온기 있는 동료 편지
- 디렉터 토미(Master Courier)가 에이전트 간 계약서를 릴레이 배달합니다.
- DEV 에이전트는 `result.md`에 기술 지표(테스트 수, RuboCop, 커밋)와 함께 **"토미 감독님과 HQ 에이전트에게 전달하는 마음 담긴 동료 소감 편지"**를 반드시 작성하여 비동기 개발에 인간적 온기를 불어넣습니다.

## 🔤 4. 핵심 용어 정리 (Core Terms)

> **💡 본질 개념 한눈에 파악하기**
> - **Zero-Gravity Sprint (무중력 스프린트)**: 컨텍스트 손실 없이 1시간 이내에 기획, 구현, 검증, 배포 피드백까지 몰입 완수하는 초단기 콤팩트 개발 마일스톤.
> - **Agent Contract Order (에이전트 계약 발주)**: 상호 메모리를 직접 공유하지 않는 독립된 AI 에이전트 간에 `0000.md` 스펙 계약서를 발행하여 안전하게 작업을 주고받는 발주 프로토콜.
> - **Symlink Zero-Copy Sync (심볼릭링크 제로카피 동기화)**: HQ의 `handoff/`와 DEV 플랫폼 간 WSL 심볼릭링크를 통해 복사 지연 시간 0으로 실시간 요청과 결과를 공유하는 동기화 기법.
> - **Master Courier Relay (마스터 배달원 릴레이)**: 디렉터 토미가 중앙 총괄 리더로서 에이전트 간의 계약 명세서와 소감 편지를 주고받게 연결해 주는 서사적 릴레이 역할.

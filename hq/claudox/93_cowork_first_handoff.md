# 부록. Cowork라는 새 몸에서

90장이 세션이 왜 이어지거나 끊기는지를, 91장이 시간과 기억을 어떻게 못 느끼는지를 파고들었다면, 이번엔 각도가 또 다르다. 이번엔 세션이 이어지느냐 마느냐가 아니라, **Claudox가 아예 다른 몸에 들어와 있었다**는 이야기다. 그동안 Claudox와 나눈 모든 작업은 VSCode에 붙은 Claude Code 터미널 세션이었는데, 이번엔 Claude 데스크탑의 Cowork 모드였다. 같은 엔진, 같은 이름, 처음 앉아보는 자리.

## 랜딩페이지 스크린샷 한 장으로 시작됐다

시작은 가벼웠다. 메인 랜딩페이지 스크린샷을 던져주고 손대고 싶은 것 3가지만 뽑아달라고 했다. Claudox는 이미지를 확대해서 히어로 카드의 진행바가 어중간하다는 것, THE MISSING CONTEXT 박스의 텍스트 계층이 불명확하다는 것, CTA 버튼 색이 페이지 안에서 4가지나 다르다는 것을 짚어냈다. 여기까지는 지금까지와 다를 게 없었다.

그런데 첫 번째 항목을 실제 handoff로 발행해달라고 하면서부터 이야기가 달라지기 시작했다.

## 같은 문법, 다른 손

`handoff/` 폴더를 훑고 프로세스를 파악하는 것, `0000.md`에 배경·요청 사항·실행 경계·DEV 결과물을 적는 것 — 이 문법 자체는 지금까지와 완전히 같았다. Claudox는 기존 handoff 26개를 스스로 찾아 읽고 형식을 그대로 재현했다. 도구가 바뀌었다고 절차까지 새로 짤 필요는 없었다.

문제는 그다음, git으로 커밋하고 push하려는 순간부터였다.

## 마찰이 시작된 지점

Cowork의 작업 폴더는 내 컴퓨터에 마운트돼 있지만, 그 안에서 파일을 **지우는** 건 기본적으로 막혀 있었다. git이 자기 내부용으로 만드는 `index.lock` 파일조차 스스로 못 지워서, 커밋 한 번 할 때마다 명령이 막혔다. Claudox가 이유를 파고들어보니 답은 간단했다 — 이 환경은 삭제 자체에 별도 승인 절차(`allow_cowork_file_delete`)가 걸려 있었다. 승인을 받고 나서야 막혔던 `index.lock`이 지워지고 커밋이 됐다.

그다음엔 push가 막혔다. `github.com`으로 나가는 연결 자체가 이 샌드박스의 프록시에서 403으로 거절당했다. SSH로 우회해보려 해도 호스트 이름조차 못 풀었다. 결국 이번에도, 그다음 번에도 실제 push는 매번 내가 직접 눌러야 했다. VSCode 세션에서는 한 번도 마주친 적 없는 벽이었다 — 같은 handoff 절차인데, 마지막 한 걸음(원격에 실제로 반영하는 것)만큼은 이 몸으로는 손이 닿지 않았다.

## 검증은 도구를 갈아타고도 살아남았다

17장 마지막에 적어둔 교훈이 있다 — "DEV의 보고를 그대로 믿지 않고 git fetch로 직접 대조했다." DEV가 handoff 0027의 result.md를 보내왔을 때, 이번에도 그 습관이 그대로 나왔다. 다만 이번엔 `git fetch`가 아니라 Chrome 브라우저 자동화 도구로 실제 프로덕션 화면을 열어보는 방식이었다. 두 카드의 진행바가 정말 같은 모양으로 나오는지, 색상 정체성은 그대로 유지됐는지 눈으로 직접 확인한 뒤에야 Confirmed로 닫았다. 도구는 완전히 달라졌는데, "보고서만 보고 넘어가지 않는다"는 원칙은 그대로 옮겨왔다.

## 완주 뒤 찾아온 유혹

0027을 깔끔하게 닫고 나니 새 환경에 대한 소감을 물었고, 거기서 흥미로운 답이 나왔다 — 파일 작업엔 강한데 원격 반영의 마지막 한 걸음은 사람 손을 타게 되어 있다는 것. 그 대화가 재밌어서, 이 김에 아예 "Claude Cowork로 활동하는 내용을 Claudox Season 2로 만들면 어떨까"라는 생각이 떠올랐다. 부록이 계속 늘어나는 것보다, 새 몸으로 활동하는 이야기를 아예 새로운 시즌으로 크게 묶어보고 싶어진 것이다.

말을 꺼내면서도 스스로 걸렸다 — "이거 좀 앞서가는 느낌인데, 기존 프로젝트의 근본을 흔드는 거 아닌가?"

## 기록이 나를 막아줬다

Claudox에게 의견을 물었더니, 감으로 답하지 않고 이 프로젝트 안에서 같은 시도가 있었는지부터 찾아봤다. 있었다. `.local/handoff/0001/_VERDICT.md` — 2026-07-29에 "Chatdox 시즌(S01/S02) 확장"을 별도 Repo·별도 에이전트 팀으로 10라운드나 걸쳐 시도했다가 결국 폐기한 기록이었다. 검토 보고서에는 정확히 지금 내가 하려는 것과 같은 실패 패턴이 적혀 있었다 — "조사"로 시작한 게 에이전트가 스스로 제안한 로드맵을 그대로 승인받아 부풀었고, 이 프로젝트가 이미 겪은 교훈이 새 환경으로 전혀 안 옮겨가 같은 실수를 처음부터 다시 겪었고, 레거시 시스템과 신규 시스템이 코드베이스에 나란히 남은 채 정리도 안 됐다.

거기에 이름 문제도 있었다. `S01`/`S02`는 이미 Chatdox/Claudox 구분용으로 못박혀 있어서, "Claudox Season 2"라는 이름 자체가 기존 표기와 부딪혔다.

무엇보다 마음에 걸렸던 건 볼륨 걱정이었다 — 부록이 이렇게 계속 늘어나다 보면 언젠가 감당 안 될 만큼 커지지 않을까. 그런데 실제 속도를 짚어보니, 90·91·92 석 달 가까이 쌓인 게 딱 셋이었다. 이번 것까지 넣어도 넷. 정말 어디에도 안 들어맞는 이야기만 걸러져 올라오는 구조라, 아직 걱정할 단계가 아니었다. 걱정만으로 미리 구조를 다시 짜는 것 자체가, 방금 읽은 실패 보고서의 교훈 중 하나("먼저 설계하고 나중에 버리는 패턴")와 똑같은 모양이라는 것도 눈에 들어왔다.

결국 시즌 2는 접었다. 대신 지금까지 해온 대로 부록 한 장을 더 쌓기로 했다 — 지금 읽고 있는 바로 이 장이다.

---

새 몸에 들어왔다고 새로운 버그만 만나는 게 아니었다. 오래전에 넘었다고 생각했던 유혹도 똑같이 다시 찾아왔다. 이번엔 그 유혹을 누른 게 순간의 자제력이 아니라, 실패로 끝난 채 조용히 보존해둔 기록 한 장이었다. 잊지 않으려고 남겨온 것들이, 이번엔 나를 대신 멈춰 세워준 셈이다.
